# Brevo API Email Integration Implementation Plan

> **For agentic workers:** Native execution in the current session.

**Goal:** Send all application email through Brevo's HTTPS transactional API so the app can run on Render Free.

**Architecture:** Keep `sendEmail` as the application interface and replace its SMTP transport with `fetch` to Brevo. Preserve database quota reservation and the development-only console fallback.

**Tech Stack:** Next.js, TypeScript, Node.js `fetch`, Brevo transactional email API, PostgreSQL.

**Spec:** `specs/viajes-sdd-spec.md`, section 12.

## Global Constraints

- Use Brevo's API over HTTPS; SMTP is not supported by Render Free.
- Keep `MAIL_DAILY_CAP` and `MAIL_MONTHLY_CAP` behavior.
- Keep Brevo credentials server-only.
- In development, missing API credentials log the email; in production, missing credentials fail.

## Review Focus

- Missing key or sender in production must fail without exposing secret values.
- A failed Brevo HTTP response must surface a useful error and leave outbox retry behavior intact.
- Text-only and HTML emails must both be supported.
